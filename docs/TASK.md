[정확 소유권과 삭제 복구 실측](HANDOFF.md#buildkit-정확-소유권과-네이티브-삭제-복구-시험) 같은 생성기로 준비한 폐기 가능한 레코드에서 6단계 전체 회수와 효과 전후 자식 종료 12건을 시험했다. 논리 회수 1건과 재실행·비대상 변경·운영 회수 영수증 각각 0건을 검증했다. 동일 오프라인 마운트의 비공개 승인 경로에서 승인 부재·불일치·재사용을 거절하고 폐기 대상 1건을 회수했다. 최초 응답 유실은 기존 영수증 조회로 정산했다. 승인된 전용 ext4의 대체 합성 캐시 1건에 실제 6단계 적용과 영수증 재조회를 검증했다. 재조회 중 변경 호출은 0건이었다. Linux ARM64 전용 제어기의 공개 API 승인·단일 적용·영수증 회수, 원장과 체크포인트 손상 6종의 변경 차단, 별도 VM 세대 유실 이후 호스트 영수증 검증을 통과했다. 이후 상시 소켓 배포 자산을 구현해 현재 Ubuntu Parallels 격리 환경에서 실제 계정·저장소·단일 적용을 실측했다. DSG 소스를 새 전용 워커의 실제 레코드와 결속하는 읽기 전용 등록과 복원 밖 최신값의 불일치 검증을 통과했다. 공개 적용의 외부 권한 비교와 요청 전 전체 복원 후 재요청 차단을 통과했다. 외부 실행 기록을 보존한 상태에서 승인·영수증 응답 직후의 RAM 복원과 외부 승인 저장소 롤백의 중복 변경을 차단했다. VM 밖 일회성 예약을 보존한 조건에서는 실제 Linux 외부 실행기의 원장과 최초 실행 표식을 함께 되감아도 합성 재변경이 0건이었고, 정상 상태 복원 후 같은 영수증을 반환했다. 지정 운영 배치와 실제 물리 전원 장애, 독립 예약까지 되감거나 외부 실행기 자체에서 예약 응답 후 RAM을 복원하는 경우는 남았다.
