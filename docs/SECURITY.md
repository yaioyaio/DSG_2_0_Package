# 보안 / 안전성 가이드

## 위협 모델
- AI가 파괴적 셸 명령 실행.
- 외부 플러그인이 프로젝트 경계를 벗어나 삭제.
- 심볼릭 링크 / junction 경유 디렉터리 탈출.
- Docker socket 직접 접근으로 프록시 우회.
- GC 계획 후 파일이 변경되는 TOCTOU.
- 멀티 에이전트가 서로의 활성 빌드·테스트 리소스를 삭제.

## 원칙
1. 기본은 read-only + dry-run.
2. 영속 볼륨, 프로젝트 소스, 사용자 자료는 자동 GC 금지.
3. 프로젝트 설정은 시스템 안전 정책을 완화할 수 없다.
4. Docker socket 직접 접근이 가능하면 `enforce`가 성립하지 않는다.
5. PID만 믿지 말고 프로세스 시작 시각과 lease 검사.
6. 재생성 가능한 캐시라도 공유 사용 여부 확인.
7. `gc apply`는 계획을 재검증하고 별도 승인 필요.
8. 플러그인은 별도 프로세스와 최소권한 적용.

## Python POC 경고
두 번째 환경변수 확인이 있지만 OS 전역 강제·활성 파일 잠금·안전한 경합 대응을 보장하지 않습니다. 실사용자의 프로젝트에서 `gc-apply` 실행을 권장하지 않습니다. POC의 Hook는 정규식 예제로 우회 가능합니다. 안전한 강제 구현으로 취급하지 마십시오.
