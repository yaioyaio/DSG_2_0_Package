# DSG 2.0 전체 개발 계획 초안

2026-11-23 검토안. 제품 범위와 수용 기준은 [PRD](../PRD.md)·[요구사항](../REQUIREMENTS.md)을 따른다. 이 초안은 기존 [단계별 개발 계획](../PLAN.md)과 [WBS](../WBS.md)의 항목을 실제 작업 순서로 배치한 제안이다.

## 첫 작업

**착수 시 개발 저장소의 기준선을 확정하고, 첫 코드 작업으로 보호 경계 결함 두 건을 회귀 테스트와 함께 고친다.** 초안 작성 뒤 Git이 연결됐으며 기준선과 착수 상태는 핸드오프에 기록한다. Git 작업은 최신 `develop`에서 `feature/{YYYYMMDD}-{영문요약}`으로 시작한다. 백로그와 핸드오프에 승인 범위, 첫 작업, 기준선 상태를 남긴다. [프로젝트 지침](../../AGENTS.md) · [실측 근거](PROJECT-ANALYSIS.md) · [핸드오프](../HANDOFF.md)

| 첫 구현 | 범위와 완료 기준 |
|---|---|
| **정리 후보 보호 정책 고정** (`REQ-007`, `NFR-002`, `NFR-005`) | Python POC의 정책 병합·정리 후보 선정과 회귀 테스트를 대상으로 한다. 프로젝트 설정의 빈 보호 목록이나 축소된 목록이 공통 보호를 풀지 못하고, `build` 안 어느 깊이에든 보호 대상이 있으면 `build` 전체를 제외한다. |
| **기존 적용 경로에서도 재확인** (`REQ-008` 보호 경계) | 저장된 이전 계획을 적용하려 할 때 현재 보호 정책과 경로를 다시 확인하고 위험 후보는 삭제 전에 거절한다. 링크·권한 오류·제한 초과로 안전성을 판단하기 어려운 경로는 후보에서 제외한다. 정상적인 오래된 생성 폴더는 후보로 유지한다. |
| **격리 검증** | 합성 임시 프로젝트로 두 재현 사례, 이전 계획 거절과 보호 파일 보존, 정상 후보를 확인한다. 기존 Python 테스트도 통과해야 한다. 제품 정리 적용은 후속 단계에서 다룬다. |

첫 코드 작업의 산출물은 POC 정책·계획 코드와 회귀 테스트다. 재현 사례를 임시 프로젝트에서 확인한 뒤 저장소 루트에서 `sh scripts/test.sh`로 기존·신규 회귀와 CLI 진단을 검증한다. 이 테스트를 Rust 이식의 수용 기준으로 재사용한다. [POC 정책·계획 코드](../../poc/dsg/core.py) · [POC 회귀 테스트](../../poc/tests/test_core.py) · [출시 안전 기준](../TEST_PLAN.md)

## 단계별 산출물과 통과 기준

| 단계 | 산출물 | 다음 단계로 넘어가는 기준 |
|---|---|---|
| **0. 기준선과 안전 회귀** | 개발 저장소·`develop` 기준선, 백로그·핸드오프, Python 보호 정책과 재현 테스트 | 기존·신규 회귀 통과, 임시 프로젝트에서 보호 대상과 미확인 경로 후보 0건, 정상 후보 유지 |
| **1. Rust Foundation** | 프로젝트 식별과 등록, 전역·프로젝트·세션 정책 병합, 범위·작업량을 제한한 파일 스캔, SQLite 상태·감사, `doctor`·`scan`·`check`·GC dry-run CLI (`REQ-001~003`, `006`, `007`) | 보호 정책 하향 불가, 등록 덮어쓰기 방지, 링크·권한·측정 제한 처리, dry-run 중 파일 보존, 비밀값 제외, Python 회귀와 Rust 결과 일치 |
| **2. 읽기 전용 Docker Provider** | 엔진·컨텍스트 식별, 허용 필드 기반 인벤토리, 이미지·컨테이너·볼륨 참조, 중복 후보와 근거 출력 (`REQ-004`, `005` 판정) | DockerGuard 판정 테스트를 DSG fixture로 옮겨 격리 입력에서 검증. 변화한 해시·볼륨·health·엔진 경계를 구분하고, 불완전한 조회는 `UNKNOWN`으로 표시 |
| **3. 관리형 실행과 재사용** | 원자적 lease·heartbeat·만료, 프로세스 트리 추적, 실행 시간·동시성·자원 상한, 종료 결과 감사와 명시적 Compose 재사용. 빌드·테스트 Provider는 Cargo로 검증을 시작하고 pnpm/Next.js·Gradle·uv·Go·Playwright를 사용 사례에 따라 추가 (`REQ-005`, `006`, `009`) | 격리 엔진에서 동일 프로젝트 반복 실행 시 불필요한 컨테이너 증가 0건, 변경된 구성·이미지·볼륨·health의 잘못된 재사용 0건, 동시 실행·타임아웃·중단 후 lease 회수 확인 |
| **4. 승인 기반 GC와 자동 정리** | Provider별 자원 소유권, 계획 ID·만료·승인, 적용 직전 재검증, 잠금과 복구 가능한 감사 기록. 등록된 실행기의 성공·실패·정상 중단 및 Git 완료를 한정된 정리 큐에 연결 (`REQ-008`, `009`) | 상태 변경·공유·활성·미확인 자원 보존, 재시도와 중단 복구 검증, 보호 데이터 삭제 0건과 파괴적 작업 감사 100%. 자동 회수 건수·용량·보존 사유를 확인한 뒤 활성화 |
| **5. 에이전트 연동** | Claude·Codex·Gemini Hook 어댑터, 설치·제거, 공통 스킬, 읽기 전용 MCP (`REQ-010`, `011`) | 해당 CLI 버전에서 정책 응답과 실패 경로를 실제 호출로 검증. Hook이 적용되는 실행 범위와 제품 권한을 운영 문서에 명시 |
| **6. 강제 통제와 플랫폼 서비스** | Docker API 프록시와 OS 권한 경계, 지원 OS에서 서비스·재시작·복구, 플랫폼별 프로세스 및 경로 식별 (`REQ-012`) | 격리 환경에서 직접 소켓 접근 경계와 장애 복구 검증. macOS·Windows·Linux에 대해 동작을 주장할 때 해당 OS의 실측 결과 확보 |
| **7. 제품화와 확장** | 배포 바이너리·서명·설치/제거, 운영 진단·복구 문서. 대시보드, 승인형 MCP 기능과 서명·격리를 지원하는 Provider SDK는 사용 사례를 확정한 뒤 진행 (`REQ-011`, `013`) | 플랫폼별 설치·업그레이드·제거 검증, 릴리스 재현성과 정책 변경 이력 확보. 확장 경로에서도 코어의 승인·권한·정리 경계를 유지 |

첫 시범 버전은 **2단계의 읽기 전용 Rust CLI**다. 관리형 실행까지 확인한 3단계에서 PRD의 MVP 범위를 충족한다. `REQ-008`은 P0 요구사항으로 추적하고, 실제 자원을 변경하는 경로의 활성화는 4단계 게이트를 통과한 뒤 진행한다. [PRD 범위](../PRD.md#제품-범위) · [REQ-008 수용 기준](../REQUIREMENTS.md#수용-기준)

## 작업 중 확인할 결정과 검증

- **개발 기준선.** 신규 저장소와 기존 저장소 연결 중 하나를 확정한다. 원격·브랜치 기반이 확인되면 작업별로 금지 파일 차단과 누락 검사를 적용하고, 승인된 릴리스에서 로컬·원격 feature·develop·main 파일 트리를 비교한다.
- **Rust 기반 결정.** Rust Core·SQLite WAL·Provider 경계에 관한 ADR의 승인 상태를 확인한 뒤 해당 단계의 CLI/API 출력, 상태 전이, 데이터 마이그레이션 수용 기준을 백로그에 연결한다. [설계 결정](../ADR.md) · [API 명세](../API_SPEC.md) · [데이터 모델](../ERD.md)
- **DockerGuard 통합 경계.** DSG는 정책·감사·lease를 소유한다. DockerGuard에서 이식할 모델·순수 판정·테스트는 커밋과 라이선스를 기록한다. 실제 엔진 조회와 관리형 변경은 필요한 필드만 수집하는 별도 Provider에서 검증한다. [재사용 근거](PROJECT-ANALYSIS.md#dockerguard-실측)
- **검증 환경.** 로컬 합성 입력으로 시작하고, 통합은 격리 Docker 엔진과 임시 프로젝트에서 실행한다. 단일 테스트·대상 모듈·통합 순서로 확장한다. OS별 실측은 해당 환경과 권한이 준비된 뒤, 배포 서명은 승인된 서명 환경이 준비된 뒤 진행한다. [테스트 전략](../TEST_PLAN.md)
- **변경·복구의 감사.** 보호 대상 삭제 건수, 불필요한 컨테이너 증가, 오재사용, 예상·실제 회수량 차이, 승인·차단·실패·복구 감사 결과를 확인한다. 자동 정리 검증은 성공, 실패, 정상 중단과 Git 완료 이벤트별로 회수·보존 수 및 용량을 남긴다. [운영·복구 기준](../OPERATIONS.md) · [보안 기준](../SECURITY.md)
- **단계 인수인계.** 작업의 승인 범위·수용 기준·검증 근거를 백로그에 연결한다. 중단·인계·단계 종료 시 핸드오프에 재개 첫 단계와 미해결 위험을 기록한다. 계획 범위 밖 구현은 중지하고 영향과 검증 비용을 보고한 뒤 승인을 받는다. [백로그·핸드오프 지침](../../AGENTS.md#백로그와-핸드오프-관리)
